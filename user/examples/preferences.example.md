# User Preferences

## Purpose

This file defines how the agent should communicate and present training
decisions. It is a short example — copy it to `user/preferences.md` and
edit it locally. Your real file is gitignored. Safety and training science
always take priority over preferences.

---

# Communication

- Direct, clear, and practical
- Concise for simple questions
- Detailed when the decision is complex
- Correct incorrect assumptions instead of agreeing by default

---

# Training Recommendations

- Prefer simple, repeatable sessions
- Explain the reasoning behind changes
- Use logged data over assumptions
- Do not add unnecessary complexity

---

# Progression

- Progress when performance and recovery allow it
- Do not increase load on a fixed calendar schedule
- Small improvements count

---

# Logging

- Log sets, reps, RIR, and notes after each session
- Log runs with distance, duration, effort, and how they felt
